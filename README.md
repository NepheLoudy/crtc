# 杜博夫赛事系统（dubov-tournament）

杜博夫系统瑞士轮（6 轮 BO1）+ 8 强车轮战淘汰赛（BO3）的赛事管理前后端。
表格化建赛录入、一键生成对阵（胜负平/重赛功能键）、实时排名大屏、全程可撤销、完全离线运行。
官方规则文本见 `docs/比赛规则.md`，系统内「使用说明 → 比赛规则」标签同文（含三天赛程表）。

## 快速开始

```bash
npm install
npm start          # 默认 http://localhost:8321，PORT 环境变量可改
```

## 账号与权限

禁止注册，账号由管理员通过 CLI 预置：

```bash
node scripts/user.mjs add <用户名> <密码> <admin|referee>   # 建号
node scripts/user.mjs passwd <用户名> <新密码>              # 改密
node scripts/user.mjs remove <用户名>                       # 删除
node scripts/user.mjs list                                  # 列表
```

| 角色 | 权限 |
| --- | --- |
| 未登录（观众/大屏） | 只读：状态、SSE 实时推送、排名 CSV |
| referee（裁判） | 录入每轮结果、确认轮次、淘汰赛录局与决赛录入 |
| admin（管理员） | 全部：建赛/销毁/设置/名册/生成对阵/退赛/撤销/审计/全量导出 |

- 密码 scrypt 加盐哈希存 `data/accounts.json`；会话持久化 `data/sessions.json`（7 天有效，同账号重登踢旧会话）。
- 服务端强制校验（前端仅做按钮隐藏）；401 未登录 / 403 权限不足。
- **可追溯**：所有变更（含登录成败与越权尝试）追加写入 `data/audit.jsonl`（谁、何时、干了什么、来源 IP），管理员在「赛前设置 → 操作日志」页查看。

## 规则实现对照（条款号对应赛程文件）

- **5.1** ARO = Σ(kᵢ × 对手当轮入场 ARO) / 已赛场次；积分分组（胜3平1负0）→ 组内 ARO 升序折叠配对（低配高）→ 批次随机。
- **5.3.1** 奇数组级联上调：自最高分组依序，从下一低分组上调 ARO 最高者；传导至最后一组仍奇数 → 组内 ARO 最低者轮空，本轮 ARO 项 = 除本组外剩余队伍 ARO 均值（首轮单组边界回退为本组均值）。
- **5.3.2** 荣誉系数：上调者胜 → 当轮对手 ARO 项 × 1.04ⁿ；下调者负 → × 0.97ⁿ。指数 n 三种口径可选（默认**当前轮数**）：`round` / `fixed1` / `streak`（连续上调/下调次数）。
- **5.3.3** 首轮 ARO = 中期考核得分总分；首轮仅一组，奇数轮空 ARO 最低者。
- **5.3.4** 弃赛：退赛状态由人工标记，标记后**规则自动推进**——本轮进行中弃赛的对局自动判负（walkover 标记），该轮 ARO 项照常入账，此后所有排序剔除该队；淘汰赛阶段走判负推进（见下表）。
- **5.3.5** 重复对位：ARO 较高者下调一组、较低者上调一组，随后重跑 5.3.1 级联；处于边界组别无法移动时强制保留并在对阵页显著告警。
- **手动调序**（2026-10-22 增补）：对阵行局号旁 ↑↓ 与相邻局互换位次，局号重编后批次/场地/时间自动重算（已录结果随局走）；端点 `/swiss/move-pairing`。
- **5.3.6** 重赛（2026-10-22 增补）：对阵行「↺ 重赛」二选一——本轮立刻重赛=清结果并将该局调至本轮最后一局、其余局次前移（裁判可操作）；下轮再重赛=本场暂记平局入 `swiss.rematchQueue`，下一轮生成时**强制对位**（豁免 5.3.5、不吃荣誉系数），队列消费制，一方停赛/弃赛自动作废并告警。
- **5.3.7** 停赛 / 弃赛 / 候补队列（2026-10-22 增补）：对阵行队伍旁「⏸」=**停赛**（本轮该局判对手胜；`t.suspended`，名册可恢复）、「弃」=**弃赛**（**候补首位顶替出战本局**，候补空则判对手胜；`t.forfeited`）；**候补队列**（`t.bench`，在册不参赛）在本轮对阵页录入多个，弃赛按序顶替、可转正/移除；候补默认全负 0 分，初始 ARO 预填 `/api/state` 的 `nextRound.medianAro`=在赛队伍中位数，奇数未补位按 5.3.1 轮空。
- **5.2** 淘汰赛：积分 → ARO 录取前 8；ARO 最高/次高为 A/B 组防守方（初始 3 分，上限 4）；其余 6 队按 ARO 序志愿选组编成进攻队列（初始 2 分）。每场 3 局制：先胜 2 局赢，对局平局=双方均失败该局，打满 3 局无人 2 胜=**平场**（双方各 -0.5，进攻方回队尾；防守方归零由进攻方接任、双方归零由顺位进攻方接任，无顺位则防守方不淘汰）。防守方胜：进攻方 -1、防守方 +0.5（封顶）；进攻方胜：防守方 -2、进攻方 +1 并互换身份。败方回队列队尾，积分 ≤ 0 持续淘汰，场上剩 2 队进入决赛（决赛平局不计、加赛至分出）。季军及 3~8 名按「车轮战胜场 → 总积分 → 瑞士轮 ARO」三级裁定。

### 退赛与判负推进

状态由人工输入、规则自动推进：胜负每轮每局由操作员手动录入；「退赛」由操作员标记（队伍行 / 控制台 ✕ 按钮），标记后系统立即按条款自动结算并推进——

| 阶段 | 自动推进逻辑（条款 5.3.4 / 5.2） |
| --- | --- |
| 瑞士轮 · 本轮有对局 | 未录入的对局自动判负（标记「弃赛判负」），该轮 ARO 项照常入账，后续轮次剔除 |
| 瑞士轮 · 本轮轮空 | 轮空无对局可判负，取消本轮轮空 |
| 淘汰赛 · 进攻方退赛 | 该场判负：防守方 +0.5（封顶）、退赛者 -1，正常开启下一场 |
| 淘汰赛 · 防守方退赛 | 该场判负：进攻方 +1 **接任防守**、退赛者 -2（身份互换照常推进） |
| 淘汰赛 · 决赛选手退赛 | 对手夺冠，退赛者为亚军 |
| 淘汰赛 · 志愿分配阶段 | 从录取名单摘除，A/B 防守方按 ARO 序重排、初始分重置 |

退赛者不再回进攻队列，之后从所有轮转剔除；积分 ≤ 0 的统一淘汰扫描照常执行，场上剩 2 队即进决赛。

### 规则未明处的设计口径（均可在「赛前设置」调整）

| 口径 | 默认 | 说明 |
| --- | --- | --- |
| 轮空得分 | 3（记胜局） | 赛程未规定轮空得分 |
| 荣誉系数指数 n | 当前轮数 | 赛程写 k=1.04ⁿ 未定义 n |
| 防守方 4 分上限 | 成为防守方瞬间及防守得分时生效 | 「进攻方 +1 无上限，转防守时超出部分被截断」 |
| 5.3.5 连带上调者 | 记上调（胜局吃 1.04ⁿ 奖励） | 被下调者的对手按规则记下调 |

## 技术结构

```
lib/engine.js      瑞士轮纯引擎（ARO 逐轮审计账目 terms，可精确回放）
lib/knockout.js    车轮战淘汰赛引擎
server/index.js    Express 入口（静态资源 + fontsource 本地字体 → 完全离线）
server/api.js      REST API + SSE 实时推送（/api/stream）
server/store.js    JSON 持久化（原子写）+ 撤销快照栈（40 步，重启不丢）
public/            无构建前端（ES Modules），战术作战室风格
test/              node:test 单元测试 + 全流程模拟赛（test/simulation.mjs）
scripts/seed.mjs   演示数据播种（走真实 HTTP API）
```

## 数据与运维

- 数据存于 `data/tournament.json`（原子写入，断电不留半截文件），已 gitignore。
- 每次变更前自动压入快照，顶栏「撤销」可一步步回退（含跨阶段），重启后撤销栈仍在。
- 每次变更通过 SSE 广播全部客户端；大屏开着即可实时看到对阵与排名更新。
- 导出：排名 CSV（带 BOM，Excel 直开）与全量 JSON（`#/setup` 右上角）。
- 无鉴权，仅限可信局域网使用；大屏页只读，不怕误触。
